## Implementation Guide

1. Review household.go and household_test.go to see which empty-result behaviour already exists. Then add a characterization test of the current single-lookup empty path before changing it.
2. Add `emptyResult(di, ip, r) *KeyedHousehold` (Household nil, Reason set). Echo the identifier only through the existing DeviceId/Ip field.
3. Add `validDeviceID(di) bool` and use it in GetHousehold. Invalid input returns emptyResult with INVALID_INPUT_FORMAT, and the lookup is skipped.
4. Wrap the Dragonfly Get and SMisMember calls in `retry` using defaultRetryAttempts and defaultRetryBase. Map redis.Nil to NO_MATCH_FOUND and a post-retry error to LOOKUP_DEPENDENCY_UNAVAILABLE.
5. Make GetHousehold and GetHouseholdFromIP return a non-nil KeyedHousehold with Reason and a nil error on every empty outcome.
6. Keep the hash-before-log pattern. Do not log raw ids or IPs, and do not restore the commented-out status.Errorf at household.go:40.

## Acceptance Criteria

- WHEN a valid device id has no record in Dragonfly THE SYSTEM SHALL return a non-nil KeyedHousehold with a nil Household, Reason NO_MATCH_FOUND and a nil error. [FR-002, FR-005, FR-010]
- WHEN the device id fails validDeviceID THE SYSTEM SHALL return Reason INVALID_INPUT_FORMAT without querying Dragonfly. [FR-003, FR-005]
- WHEN Dragonfly returns a non-redis.Nil error through all retry attempts THE SYSTEM SHALL return Reason LOOKUP_DEPENDENCY_UNAVAILABLE with a nil error. [FR-004, FR-005, FR-009]
- WHEN any empty-result path executes THE SYSTEM SHALL leave raw device ids and IPs out of logs and reason content. [FR-007, FR-008, NFR-004, NFR-005]
- WHEN a lookup finds a match THE SYSTEM SHALL return the household exactly as before, with an unspecified reason. [FR-006, FR-010]

## Summary
Enhance the `household-id-adornment-api` no-results path so every empty lookup carries exactly one distinct, named, privacy-safe diagnostic reason — 'no match found', 'invalid input format', or 'lookup dependency unavailable'. The reason is introduced from scratch as the proto contract's first `enum` plus a new field (tag 4) on `KeyedHousehold` in `household-id-adornment-proto`, consumed by the Go service which maps two of the three reasons onto existing control-flow branches, adds net-new device-path input validation for the third, and wraps Dragonfly calls in bounded retry (verified live across both repos).

## Spec Excerpts

#### FR-009 — Dependency calls use bounded retry before reporting unavailable

```gherkin
Given a household ID lookup requires a call to a downstream lookup dependency
  And that dependency fails or times out
When the API attempts the dependency call
Then the API retries using bounded retry with exponential backoff (default: up to 3 attempts), never retrying indefinitely
  And if a rate-limit response is received, the API honors the response's Retry-After indication rather than retrying on a fixed schedule
  And only after the bounded attempts are exhausted does the API return the "lookup dependency unavailable" reason per FR-004
```

## Implementation Guide

1. Create internal/householdserver/retry.go in package householdserver, following the style of key.go and household.go.
2. Define `defaultRetryAttempts = 3` and `defaultRetryBase`.
3. Implement `retry[T any](ctx, attempts, base, fn) (T, error)`. Return redis.Nil (go-redis v9) immediately with no retry.
4. Retry any other error up to `attempts` total tries, sleeping base*2^n between tries. Stop early if ctx is cancelled.
5. Return the last error wrapped.
6. Create retry_test.go with table-driven cases: immediate success, redis.Nil with one call, transient failure then success, all attempts failing, and ctx cancelled mid-backoff.

## Acceptance Criteria

- WHEN fn returns redis.Nil THE SYSTEM SHALL return it after exactly one call, with no retry. [FR-009]
- WHEN fn keeps returning a non-Nil error THE SYSTEM SHALL stop after `attempts` total calls and return the last error wrapped. [FR-009, NFR-002]
- WHEN fn fails once and then succeeds THE SYSTEM SHALL return the successful value and a nil error. [FR-009]
- WHEN ctx is cancelled during backoff THE SYSTEM SHALL return promptly without further attempts. [NFR-002]
- WHEN retries occur THE SYSTEM SHALL wait base*2^n between attempts. [FR-009, NFR-002]
- Existing tests pass
- New functionality has test coverage
- Code follows repository conventions (see CLAUDE.md)

## Implementation Guide

1. In the GetHouseholds loop in household.go, stop skipping items whose lookup returns an empty result.
2. Append every KeyedHousehold to the response, both hits and reason-only entries from T004.
3. Make sure a batch containing only misses returns a non-nil response with one reason entry per input.
4. Preserve existing ordering and hit behaviour so current callers still work.
5. Add table-driven batch cases to household_test.go: all hits, mixed, all misses, and a dependency-unavailable item. Assert one entry per input and the correct reasons.

## Acceptance Criteria

- WHEN a batch has a mix of matches and misses THE SYSTEM SHALL return one entry per input, with the household populated for hits and a Reason for misses. [FR-002, FR-005, FR-010]
- WHEN every batch item misses THE SYSTEM SHALL return a non-nil response containing one reason entry per input. [FR-002, FR-005]
- WHEN a batch item has invalid input THE SYSTEM SHALL return INVALID_INPUT_FORMAT for that item only. [FR-003, FR-005]
- WHEN Dragonfly is unavailable for a batch item THE SYSTEM SHALL return LOOKUP_DEPENDENCY_UNAVAILABLE for that item. [FR-004, FR-005]
- WHEN an all-hit batch is processed THE SYSTEM SHALL return the same results as before. [FR-010]
- Existing tests pass
- New functionality has test coverage
- Code follows repository conventions (see CLAUDE.md)

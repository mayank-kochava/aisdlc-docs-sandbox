## Summary
Enhance the `household-id-adornment-api` no-results path so every empty lookup carries exactly one distinct, named, privacy-safe diagnostic reason — 'no match found', 'invalid input format', or 'lookup dependency unavailable'. The reason is introduced from scratch as the proto contract's first `enum` plus a new field (tag 4) on `KeyedHousehold` in `household-id-adornment-proto`, consumed by the Go service which maps two of the three reasons onto existing control-flow branches, adds net-new device-path input validation for the third, and wraps Dragonfly calls in bounded retry (verified live across both repos).

## Implementation Guide

1. Edit household_service.proto (the plan places it at pkg/householdservice/): add `enum NoResultReason` with NO_RESULT_REASON_UNSPECIFIED=0, _NO_MATCH_FOUND=1, _INVALID_INPUT_FORMAT=2, _LOOKUP_DEPENDENCY_UNAVAILABLE=3.
2. Add `NoResultReason reason = 4;` to the KeyedHousehold message. Leave all existing tags untouched, and add proto comments describing each reason.
3. Regenerate stubs with `make protoc-compile`. On Linux, work around the macOS-only `sed -i ''` at Makefile:49.
4. Confirm the regenerated files under go/householdservice and python/householdservice (pb2.py, pb2.pyi, pb2_grpc.py) are updated. Do not hand-edit them.
5. Create go/householdservice/household_service_reason_test.go. Assert the four enum values and that GetReason() defaults to UNSPECIFIED.
6. In the same test, marshal a KeyedHousehold with reason set and unmarshal it into a message without the field, asserting no error.

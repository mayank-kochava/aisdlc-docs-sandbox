# T002: Cache with Get, Put, eviction and default capacity

## In short

Adds the cache itself: store and look up values, drop the least recently used entry when full, and report how many entries it holds. When no valid capacity is given it falls back to a default size that the owner must supply, and the agent must not make one up.

## Implementation Guide

1. Before writing the default capacity, ask the owner (Mayank) for the number. FR-4 says it is not in the spec and must not be guessed. If no answer is available, stop and report the task as blocked on that question rather than choosing a value.
2. Create lru/cache.go in package lru. Define `Cache` with a capacity, a `map[string]*node` and a `list` from T001. Use the standard library only and make no go.mod changes.
3. Implement `New(capacity int) *Cache`. For capacity <= 0, use the owner's value, held in a named constant `defaultCapacity` with a comment saying the owner (Mayank) chose it.
4. Implement `Get(key string) (string, bool)`: look up the map, call `moveToFront` on a hit and return the value, true. On a miss return `"", false`. Use only the map and the list pointers, with no scanning, to keep Get O(1).
5. Implement `Put(key, value string)`: if the key exists, update its value and `moveToFront`. Otherwise, if at capacity, call `removeBack` and delete the evicted key from the map. Then `pushFront` a new node and store it in the map. This keeps Put O(1). Implement `Len() int` to return the current number of entries.
6. Write table-driven tests in lru/cache_test.go covering hit and miss, update of an existing key, eviction order after Get changes recency, Len, and New(0) and New(-1). The default-capacity tests must refer to the `defaultCapacity` constant, not a hard-coded number.

## Acceptance Criteria

- WHEN New is called with a positive capacity N and more than N distinct keys are Put THE SYSTEM SHALL keep Len() equal to N. [FR-1]
- WHEN Get is called for a present key THE SYSTEM SHALL return its value and true and mark the key most recently used, and WHEN the key is absent THE SYSTEM SHALL return "" and false. [FR-2]
- WHEN Put is called on a full cache with a new key THE SYSTEM SHALL evict the least recently used entry first, so that a prior Get on the oldest key causes the next-oldest to be evicted instead. [FR-3]
- WHEN Put is called with a key that already exists THE SYSTEM SHALL update its value and mark it most recently used without evicting any entry or changing Len. [FR-3]
- WHEN New is called with 0 or a negative capacity and defaultCapacity+1 distinct keys are Put THE SYSTEM SHALL keep Len() equal to defaultCapacity and evict the oldest key. [FR-4]
- Existing tests pass
- New functionality has test coverage
- Code follows repository conventions (see CLAUDE.md)

## Implementation Guide

1. Create lru/list.go in package lru, standard library only; do not use container/list.
2. Define `node` (key, value string; prev, next *node) and `list` (head, tail *node; size int) exactly as in the task interface. The head is the most recently used entry and the tail is the least.
3. Implement `(l *list) pushFront(n *node)`, which links n at the head, sets tail when the list was empty, and increments size.
4. Implement `(l *list) moveToFront(n *node)`, which unlinks n from its current position and re-inserts it at the head using only prev/next pointer updates, with no traversal. Handle n already being the head and n being the tail.
5. Implement `(l *list) removeBack() *node`, which unlinks and returns the tail, decrements size, and returns nil when the list is empty.
6. Write table-driven tests in lru/list_test.go covering an empty list, a single node, moving the head, middle and tail nodes, and repeated removeBack. After each operation, check the prev/next links, head, tail and size.

## Acceptance Criteria

- WHEN pushFront is called on an empty list THE SYSTEM SHALL make the node both head and tail with size 1. [FR-2]
- WHEN pushFront is called on a non-empty list THE SYSTEM SHALL make the new node the head, link it to the previous head, leave the tail unchanged and increase size by one. [FR-2]
- WHEN moveToFront is called on the head, a middle node or the tail THE SYSTEM SHALL make that node the head, keep head, tail and neighbour links consistent, keep the other nodes in their relative order, and leave size unchanged. [FR-2]
- WHEN removeBack is called on a non-empty list THE SYSTEM SHALL unlink and return the tail node (the least recently used), make the previous node the new tail, and decrease size by one. [FR-3]
- WHEN removeBack is called on an empty list, or after the last node has been removed, THE SYSTEM SHALL return nil and leave head, tail nil and size 0. [FR-3]

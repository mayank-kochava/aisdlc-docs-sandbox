## Implementation Guide

1. Open an SRE-owned issue for this change and keep it separate from every application-code task. Get the local SSD count N from SRE before editing, because N is still an open item and no value is invented here.
2. Follow eng-plan rather than the task text. The task names the existing `s-n4-std-8-airbyte` pool, but eng-plan says local SSD is a pool-wide property and that pool is shared by other job types. So add a new dedicated pool in `ko-infrastructure/service/qa/platformmesh/greedy_goat.tf` (eng-plan example name `s-n4-std-8-blend-combine`, Spot VMs, ~24 vCPU ceiling as a starting point). Leave the `s-n4-std-8-airbyte` block untouched.
3. Read `modules/beta-private-cluster/cluster.tf` from the pinned `terraform-google-modules/kubernetes-engine` module at tag `v41.0.1` to re-confirm that `local_ssd_ephemeral_storage_count` is the field that backs `emptyDir` with local SSD. This is a read-only upstream file. Do not commit edits to it.
4. On the new pool, set `local_ssd_ephemeral_storage_count = N`. Do not use `local_ssd_count`, `local_ssd_ephemeral_count` or `local_nvme_ssd_count`.
5. Give the new pool a taint with key `blend-combine-workload`. This task defines that taint name. T033 (`BlendCombineJobPodFactory.kt`) and T203 consume it, so no dependency on T033 is needed here. Record the pool name and taint key in the issue for those tasks.
6. Run `terraform validate` and `terraform plan` for `ko-infrastructure/service/qa/platformmesh`. Confirm the plan only adds the new pool and shows no change to `s-n4-std-8-airbyte`.

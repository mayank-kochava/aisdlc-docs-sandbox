## Implementation Guide

1. Identify who owns the key-prefix scheme of the shared GCS storage bucket, and name them in the record you write.
2. Propose `blend-staging/` for per-source Parquet staging data, following the existing separation of log/state/workloadOutput/activityPayload/auditLogging prefixes. Also propose `blend-output/`, which eng-plan says `BlendCombineJob.kt` writes combine output to, so both are agreed together.
3. In `docs/16-PRDs/080-kochava-elt-blending/eng-plan.md`, add one line of the form `**Prefix decision**: <owner name>, <date>: staging=<prefix>, output=<prefix>` with the agreed strings (use `blend-staging/` and `blend-output/` unless the owner changes them).
4. If the owner changes either prefix, also correct the `blend-staging/` and `blend-output/` mentions elsewhere in eng-plan.md so the document is consistent.
5. Make no bucket, IAM, Terraform or application-code changes unless the owner explicitly requires them, in which case open a separate task.

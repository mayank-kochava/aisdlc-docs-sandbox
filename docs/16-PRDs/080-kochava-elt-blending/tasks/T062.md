### What actually shipped (2026-09-29)
- **Backend account-scoping (Parts A3/A4)** — `AccountContextFilter` + `CurrentAccountContext`/
  `RequestAccountContext`, rolled out to all eleven Kochava controllers/handlers. Every endpoint
  moved from `/api/v1/kochava/<resource>` to `/api/v1/kochava/accounts/{accountId}/<resource>`,
  and every request DTO had its client-supplied `accountId` field removed.
  [Backend PR #158](https://github.com/Kochava/airbyte/pull/158).
- **Workspace-per-account (Part A5) + read-proxy (Part A6)** — `account_workspaces` table
  (`V1_0_0_029__CreateAccountWorkspacesTable.kt`), `AccountWorkspaceProvisioningService`, and
  `AccountConnectorsController`/`AccountConnectorsHandler`. Same PR #158.
- **Gateway routing mechanics (Part C1, partially)** — a single Oathkeeper rule captures the
  numeric `accountId` from the URL path and injects it as a header for `AccountContextFilter`
  to check. **Shipped without the planned authentication/authorization layer** — see "What's
  still a live gap" below; this is the one place the shipped version diverges from the plan in
  a way that matters for security, not just sequencing.
  [ko-k8s-apps PR #19817](https://github.com/Kochava/ko-k8s-apps).

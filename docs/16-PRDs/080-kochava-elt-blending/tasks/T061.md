## Implementation Guide

1. Read `PipelineHandler.completeWizard` and determine whether it already rejects a `destinationId` that belongs to another account. The task is marked unconfirmed, so do not assume either way.
2. If the check is missing, add a lookup of the destination's account in `completeWizard`. Reject the request when the account differs from the caller's account, using the existing typed-exception-to-HTTP-status convention (no `{data,error}` envelope).
3. If the check already exists, make no production change and record the finding in the PR description.
4. Add or extend a unit test for `PipelineHandler.completeWizard` (JUnit 5 + MockK) covering the same-account success case and the cross-account rejection case.

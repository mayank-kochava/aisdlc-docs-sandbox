## User Story

**US1**

**Acceptance:**
- FR-2: `Allow() bool` takes one token if available and returns true; otherwise returns false without blocking.
- FR-3: Refill is computed lazily from elapsed clock time on each call (no goroutines, no timers). Fractional tokens carry over between calls.
- FR-5: `Tokens() float64` returns the current token count after refill. Safe for concurrent use.

```
  - `TestFractionalCarryOver`: repeated sub-token advances (e.g. 4 × 250ms at rate 1/s) accumulate to exactly one token and allow one request.
  - `TestBurstAfterIdle`: after a long idle period (far more than `burst/rate`), `Tokens()` is capped at `burst` and exactly `burst` consecutive `Allow()` calls succeed before the next fails.

```

## Implementation Guide

1. Create `ratelimit/edge_test.go` with table-driven tests using `NewFakeClock` and `Advance`. Tests must not sleep.
2. Write `TestAllowAtExactRefillBoundary`: rate 1/s, burst 1, drain the bucket, then check `Allow()` is false at 999ms and true at exactly 1s.
3. Write `TestFractionalCarryOver`: advance 4 × 250ms at rate 1/s and assert the sub-token advances accumulate to exactly one token and allow one request.
4. Write `TestBurstAfterIdle`: after a very long idle period, assert `Tokens()` is capped at `burst` and exactly `burst` `Allow()` calls succeed before the next fails.
5. Write `TestNoRefillWithoutTimeAdvance`: repeated `Allow()` and `Tokens()` at the same clock instant change the count only by the spend.
6. Run `go test -race ./ratelimit/...` and `go vet ./...`. Do not change `limiter.go`; if a test fails, report the defect.

## Acceptance Criteria

- WHEN the clock is 999ms after draining a rate 1/s, burst 1 limiter THE SYSTEM SHALL return false from `Allow()`, and WHEN exactly 1s has elapsed THE SYSTEM SHALL return true. [FR-2]
- WHEN four 250ms advances occur at rate 1/s THE SYSTEM SHALL have accumulated exactly one token and allow one request. [FR-3]
- WHEN the clock advances far beyond `burst/rate` THE SYSTEM SHALL cap `Tokens()` at `burst` and allow exactly `burst` consecutive `Allow()` calls. [FR-3]
- WHEN `Allow()` and `Tokens()` are called repeatedly without advancing the clock THE SYSTEM SHALL change the token count only by tokens spent. [FR-5]

## Implementation Guide

1. Create `ratelimit/limits_test.go` with table-driven tests using a shared `NewFakeClock`. Tests must not sleep.
2. Write `TestIndependentLimiters`: build several limiters in a `map[string]*Limiter` on one fake clock, drain one, and assert the others are unaffected and refill on their own state.
3. Write `TestInvalidLimits` with cases for rate 0, negative rate, burst 0, negative burst, both invalid and a nil clock. Assert each does not panic and returns a non-nil limiter.
4. In `TestInvalidLimits`, assert that limiters built from different invalid inputs behave the same: for the both-invalid cases, `Tokens()` is equal at the start and the `Allow()` sequence is identical as the fake clock advances.
5. Check whether the owner (Mayank) has provided the default rate and burst. If so, add assertions against them; if not, ask for them and do not guess. Until then, leave out any assertions on specific default numbers.
6. Run `go test -race ./ratelimit/...` and `go vet ./...`.

## Acceptance Criteria

- WHEN one limiter in a set sharing a fake clock is drained THE SYSTEM SHALL leave the other limiters' `Tokens()` values unchanged. [FR-1]
- WHEN the fake clock advances after one limiter in a set was drained THE SYSTEM SHALL refill each limiter according to its own state. [FR-1]
- WHEN `New` is called with rate <= 0, burst <= 0, both invalid, or a nil clock THE SYSTEM SHALL not panic and SHALL return a non-nil limiter whose first `Allow()` returns true. [FR-4]
- WHEN `New` is called with both rate and burst invalid, in any combination of zero and negative values, THE SYSTEM SHALL return limiters with equal `Tokens()` and identical `Allow()` results over the same fake-clock advances. [FR-4]

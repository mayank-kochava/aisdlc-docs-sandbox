## Implementation Guide

1. Write failing tests in `cmd/soccer-v2/handler_test.go`: `TestHandle_ConditionalFlaggedSanitizedToPostbacks`, `TestHandle_ConditionalUnflaggedOriginalToBoth` and `TestHandle_NonConditionalUnchanged`.

3. Create `cmd/soccer-v2/restriction.go` with `isRowLevelRestricted(p *control.Postback) bool`, which reads `kochava.device.attribution.row_level_restricted` and treats an absent flag as not restricted.
4. In `Handler.Handle` (`cmd/soccer-v2/main.go`, around :261-300), when `SanitizeKeypaths && RequireRestrictionFlag` and the postback is not flagged, write the original to both `postbacks` and `postbacks_unredacted`.
5. Otherwise, including flagged postbacks and every config without the option, keep the existing sanitize path.
6. Run the CI command.

## Acceptance Criteria

- WHEN the config has `SanitizeKeypaths` and `RequireRestrictionFlag` and the postback is flagged THE SYSTEM SHALL write the sanitized copy to `postbacks` and the original to `postbacks_unredacted`. [FR-010]
- WHEN the config has `RequireRestrictionFlag` and the postback is not flagged THE SYSTEM SHALL write the original to both `postbacks` and `postbacks_unredacted`. [FR-011]
- WHEN the config does not set `RequireRestrictionFlag` THE SYSTEM SHALL behave byte-identically to the current path. [BR-1]
- WHEN the flag is absent from the postback THE SYSTEM SHALL treat it as show. [BR-6]
- WHEN a flagged postback is sanitized THE SYSTEM SHALL keep the row and mask only the configured keypaths. [BR-3]

- New functionality has test coverage

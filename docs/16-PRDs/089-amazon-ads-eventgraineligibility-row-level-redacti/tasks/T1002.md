### Group E — Control: Postback / CAP Redaction

> Postbacks/CAP are applied by **Control at send time**, not read-time; sanitization-api only serves config and never masks. See BR-11 for the open decision on postbacks to Amazon itself.

**FR-040 — Flagged conversion postbacks redacted at send time**
```gherkin
Given a 13954 conversion has row_level_restricted = true
When Control sends a postback or CAP integration event for the conversion
Then Control applies the sanitization-api keypath configuration to redact the Amazon-sourced fields before sending
```

**FR-041 — Unflagged conversion postbacks sent unredacted**
```gherkin
Given a 13954 conversion does not have row_level_restricted = true
When Control sends a postback or CAP integration event for the conversion
Then Control sends the Amazon-sourced fields unredacted
```

**FR-042 — Postback to Amazon's own endpoint stays raw (pending decision)**
```gherkin
Given a 13954 conversion has row_level_restricted = true
  And the postback destination is the attributed network's own endpoint (Amazon itself)
When Control sends the postback
Then Control sends the conversion raw by default (per the open product decision referenced in BR-11)
```

## Implementation Guide

1. In Postback.php, add public static postbackIsRowLevelRestricted(array $postback): bool. It checks the postback for the row_level_restricted flag on the attribution.
2. Add public static filterKeypathsForRestriction($keypaths, array $postback). It returns null for null input. It returns null when require_restriction_flag is true and the postback is not flagged. Otherwise it returns $keypaths unchanged.
3. In the keypath application in Postback::Sanitize (retrieveKeyPaths use, around :1640-1695), pass the keypaths through filterKeypathsForRestriction before applying them.
4. Keep the existing skip of keypaths for the attributed network's own template (BR-11), and keep the soccer Kafka payload unredacted.
5. Write failing tests first in Postback_test.php: conditional config with flagged postback redacts; with unflagged postback is untouched; non-conditional config is unchanged; CAP is covered; Kafka payload is never redacted. Run them in the control-cover:ci image.

## Acceptance Criteria

- WHEN the config has require_restriction_flag true and the postback is flagged THE SYSTEM SHALL apply the keypath redaction to it. [FR-040, BR-8]
- WHEN the config has require_restriction_flag true and the postback is not flagged THE SYSTEM SHALL leave the postback unredacted. [FR-041]
- WHEN the config does not set require_restriction_flag THE SYSTEM SHALL apply keypaths exactly as before. [NFR-008]
- WHEN the postback goes to the attributed network's own endpoint THE SYSTEM SHALL keep it raw. [BR-11]
- WHEN filterKeypathsForRestriction receives null keypaths THE SYSTEM SHALL return null. [FR-042]
- Existing tests pass
- New functionality has test coverage
- Code follows repository conventions (see CLAUDE.md)

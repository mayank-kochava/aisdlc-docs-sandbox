## Implementation Guide

1. In tools/reconciliation_tools.py, confirm which `changeSource` the outbound `configure_reconciliation` POST in `_set_reconciliation_settings` sends. dash-api only emits `warnings[]` when `changeSource` is not `console`. If it is `console` or unset, flag this as a blocker rather than silently continuing.
2. Change `_set_reconciliation_settings` to return `tuple[dict[str, Any], list[str]] | str`, meaning (data, warnings). Read `result.get('warnings')` from the write response and default it to an empty list. Error strings are returned unchanged.
3. Update every caller of `_set_reconciliation_settings` in tools/reconciliation_tools.py to unpack the tuple. This includes the `write_result` handling in `kochava_set_attribution_windows`.
4. In `kochava_set_attribution_windows`, keep the read/merge/post flow and retry behaviour unchanged. After the final read-back, if the captured warnings are non-empty and the result is a dict (`not isinstance(result, str)`), return it with `status: "success_with_warnings"` and `warnings: [...]` copied verbatim from the write leg.
5. When there are no warnings, return exactly the same plain-success shape as today. Do not pre-round `equal_priority_window` values.
6. In unit-tests/test_reconciliation_tools.py, patch `_set_reconciliation_settings` to return a warning payload such as 'equal_priority_window dropped: network does not support CTV impressions'. Assert `status == "success_with_warnings"` and that `warnings` is verbatim. Add a no-warning test asserting the unchanged plain success, and re-run `TestAttributionWindowsSettingsSchema`.

## Acceptance Criteria

- WHEN dash-api's write response contains a non-empty `warnings` list THE SYSTEM SHALL return a dict with `status` equal to `success_with_warnings` and a `warnings` list containing the warning text verbatim. [BR-7, FR-009]
- WHEN dash-api's write response has no warnings or an empty list THE SYSTEM SHALL return the same plain-success result as before this change. [FR-010, BR-8]
- WHEN `_set_reconciliation_settings` succeeds THE SYSTEM SHALL return a `(data, warnings)` tuple, and WHEN it fails THE SYSTEM SHALL return the same error string as before. [BR-7, BR-8]
- WHEN warnings are attached THE SYSTEM SHALL still include the read-back settings in the result and SHALL leave the read/merge/post flow and retry policy unchanged. [BR-8, FR-011]
- WHEN the final result is a string rather than a dict THE SYSTEM SHALL return it as-is without raising an error while trying to attach warnings. [BR-7, BR-8]

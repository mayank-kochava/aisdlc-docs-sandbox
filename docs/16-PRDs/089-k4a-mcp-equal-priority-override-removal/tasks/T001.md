Existing `_validate_settings(settings: dict[str, str]) -> str | None` in tools/reconciliation_tools.py (returns an 'Error: ...' string or None). ## Implementation Guide

1. In tools/reconciliation_tools.py, read `_validate_settings` and the `kochava_set_attribution_windows` body. Check whether `equal_priority_window='-1'` and `reconciliation_appstore_search_exception` are handled correctly today. The eng-plan says they already are, but the task text says the numeric branch rejects negatives.
2. Add constants `_EQUAL_PRIORITY_WINDOW_KEY = "equal_priority_window"` and `_APPSTORE_SEARCH_EXCEPTION_KEY = "reconciliation_appstore_search_exception"`.
3. Add `_validate_equal_priority_window(value: object) -> str | None`. It accepts only `-1`, `0`, or a value from 1/60 to 24 hours. It returns an 'Error: ...' string naming the valid values, so 25 is rejected. It does not pre-round the value.
4. Add `_validate_appstore_search_exception(value: object) -> str | None`. It accepts only `0` or `1` and rejects wrong types and other values with an error naming the valid values.
5. In `_validate_settings`, route these two keys to the new helpers before the generic numeric lookback branch. Leave all other keys on their current path. Keep validation running before any dash-api call, and forward `-1` literally.
6. In unit-tests/test_reconciliation_tools.py, add or confirm tests. Valid cases: -1, 0, 1/60, 24, and 0/1 for the exception. Invalid cases: 25, -2, non-numeric, and a wrong type. Also assert that no downstream call is made on rejection. Keep `TestAttributionWindowsSettingsSchema` passing.

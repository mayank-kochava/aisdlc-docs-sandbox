## Spec Excerpts

### Decision: Keep the change entirely in Python / FastMCP within `k4a-mcp-server`

**Chosen**: Implement all FRs in `k4a-mcp-server` (Python ≥3.11, FastMCP 2.12.4, aiohttp). No new dependencies.

**Rationale**:
- Investigation confirmed the root cause lives entirely in `tools/reconciliation_tools.py` `_validate_settings` (CA-1, k4a-mcp-server) and the `_set_reconciliation_settings` helper (CA-7). The `math` module needed for the range check is already imported (CA-1, line 22).
- Spec §5 explicitly excludes dash-api, console, and other MCP tools. Grep confirmed zero occurrences of the three keys anywhere in the repo today (CA-6), so there is no hidden coupling.
- KG evidence confirms `k4a-mcp-server` is the single affected backend repo (confidence: high).

**Alternatives Considered**:
1. **Change the server-side validation in dash-api**
   - Pros: single source of truth for bounds.
   - Cons: out of scope (§5); dash-api already validates correctly (CA-2, dash-api). The whole point of the PRD is the MCP tool should reject invalid input *before* the HTTP call to avoid the retry loop.
   - Rejected: dash-api is the authority and is already correct; the gap is purely client-side.

**Implementation Notes**:
- Tests: pytest, `asyncio_mode = auto` (`pytest.ini`), run via `python unit-tests/run_tests.py`. Tools are invoked in tests via `._internal(...)` (CA-9).
- Lint: CI runs `ruff check` **only on PR-changed `.py` files** — new/edited lines must pass ruff; pre-existing debt elsewhere is tolerated.

## Summary
This change makes the K4A MCP tool `kochava_set_attribution_windows` able to remove a partner's CTV Equal Priority override (via `equal_priority_window = -1`) and to validate CTV-related keys correctly client-side, mirroring dash-api's contract exactly. The work is fully self-contained in `Kochava/k4a-mcp-server` (Python 3.11+, FastMCP): two bespoke validation branches, a two-part warnings capture-and-attach, a docstring extension, and unit tests. No dash-api, schema, or deploy changes.

## Implementation Guide

1. In `_set_reconciliation_settings` in `tools/reconciliation_tools.py` (around lines 155-165), capture the top-level `result.get("warnings")` as well as `data`. Return both as a `(data, warnings)` tuple, and do not modify `tools/k4a_api_tools.py`.
2. Update the caller in `kochava_set_attribution_windows` to unpack `(data, warnings)`. Keep the error-string handling, retry policy and merge-before-write flow unchanged.
3. On the final read-back result, set `result["warnings"] = warnings` only when warnings are non-empty, and only when `not isinstance(result, str)` so error strings pass through unchanged.
4. Update any existing test in `unit-tests/test_reconciliation_tools.py` that patches or mocks `_set_reconciliation_settings` so it matches the new return shape.
5. Check whether the outbound `configure_reconciliation` request sends a change-source of `"console"`. dash-api suppresses the drop-warning in that case. If it does, flag it in the PR and do not change request plumbing here.
6. In `unit-tests/test_reconciliation_tools.py`, add a test where the set response carries top-level warnings and assert they appear in `result["warnings"]`. Add a no-warnings test (no `warnings` key) and an error-string passthrough test.

## Summary
This change makes the K4A MCP tool `kochava_set_attribution_windows` able to remove a partner's CTV Equal Priority override (via `equal_priority_window = -1`) and to validate CTV-related keys correctly client-side, mirroring dash-api's contract exactly. ## Implementation Guide

1. In tools/reconciliation_tools.py, add a bespoke `equal_priority_window` branch in `_validate_settings`, placed before the generic numeric `else` that rejects negative values.
2. Accept -1, 0, or a finite h with 0.016666666666666666 <= h <= 24.0. Use `math.isfinite` (math is already imported). Use the full float spelling for the lower bound.
3. Reject every other value by returning a non-empty error string. The string must name the valid values (-1, 0, 1/60 to 24 hours) and say that -1 means use the app default.
4. Leave `equal_priority_enabled` untouched so it passes through unchanged. Leave all other keys, the retry policy and tools/k4a_api_tools.py unchanged.
5. In unit-tests/test_reconciliation_tools.py, carve out the existing parametrized `test_non_finite_or_negative_lookback_value_...` test (around :466-481) so -1 is valid for `equal_priority_window` only. -1 must still be rejected for other lookback keys. Do this in this task so the whole test file stays green.
6. In the same file, add direct `_validate_settings` tests covering -1, 0, 6 and 1/60 as valid, and 25, -2 and non-finite values as invalid with the expected message content. Add an end-to-end test that calls the tool via `._internal(...)` with 25 and with -2 and asserts the get and set mocks are never called.

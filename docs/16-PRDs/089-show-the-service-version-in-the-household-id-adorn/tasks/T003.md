## Implementation Guide

1. Start this task only after the T002 handler change is merged and the T001 Dockerfile stamping fix is in place. The probe check needs the new `OK - <host> - <version>` body, and the smoke check needs a correctly stamped release.
2. In Kochava/ko-k8s-apps, open adornment/household-id/api/base/api.yaml and read the liveness and readiness probe definitions for `/healthcheck` (around lines 87-97).
3. Check the prod and qa overlays (e.g. adornment/household-id/api/prod/api.yaml) for probe overrides. Confirm every probe is a status-only `httpGet` (no exec, tcpSocket or body matching) by running the test_cmd.
4. Edit manifests only if a probe depends on the response body text. Otherwise leave all manifests unchanged.
5. Post a PR comment on the T002 PR recording the probe verification outcome and the smoke-check procedure: request `/healthcheck` on the deployed pod and confirm the version after `OK - <host> - ` equals the released tag, not `unknown` or `dev`.
6. After rollout, run that smoke check and add the result to the same PR comment.

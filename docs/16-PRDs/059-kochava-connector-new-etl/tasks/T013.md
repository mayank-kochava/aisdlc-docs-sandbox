# Country Code "ALL" Region Handling Fix

## Overview

When consolidation rules specify `Region: "ALL"`, it means "include all countries" - no filtering should be applied. However, several SQL generators were incorrectly treating "ALL" as a literal country code, generating queries like:

WHERE LOWER(country_code) IN ('all')

This only matches rows where `country_code = 'all'` instead of including all countries.

**Correct behavior:** When "ALL" is in the region list, omit the WHERE clause entirely.

## Implementation Guide

1. Create data-model.md in docs/16-PRDs/059-kochava-connector-new-etl/ if it does not already exist. Add a section titled "Sample MongoDB Document (Sharawmer)" whose JSON follows the property names in KochavaRedshiftConfigModel.cs. If the file already has that section, reuse its structure unchanged.
2. Get the real values for Server, DatabaseName, Schema, Table, the AppAssociations KochavaId/AppId pairs and AdvertiserId from ops or the Sharawmer owner. Record who supplied them on the ticket. Do not guess them or leave placeholders.
3. Set ConnectorType to "KochavaRedshift". Set LookbackWeeks greater than 0, CountryCodes to ["sa"], and a non-empty CohortPeriods and metric event mapping, as in the sample.
4. Insert the document into the `data_supplier_configs` MongoDB collection for the target environment.
5. Record the resulting configId on the ticket, since the T016 run needs it.

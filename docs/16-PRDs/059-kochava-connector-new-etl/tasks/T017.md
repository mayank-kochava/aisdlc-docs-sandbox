## Implementation Guide

1. Precondition check: query the Sharawmer `_main` table on the dev feature store (name from the existing `KochavaRedshiftFeatureStoreTableDefinitions.GetTableDefinitions(...)` MainTable) and confirm it has rows. If it is empty, first run `dataimport.kochavaredshift` for the Sharawmer configId and wait for it to succeed. Treat this as a manual precondition, not a declared task dependency.
2. Confirm the T008 (`KochavaRedshiftDataAggregator` / `KochavaRedshiftDataConsolidator`) and T016 changes are deployed to dev.
3. Trigger the `dataconsolidation` task for the Sharawmer configId on dev and capture the ETL pod log for that run.
4. Search that pod log for `Fatal` or `LogTaskFailure` entries from `IApplicationLogger`. Record whether any exist.
5. Using the `AggregateTable.TableName` from the same `GetTableDefinitions(...)` result, run `SELECT COUNT(*) FROM <aggregate_table>;` and `SELECT campaign_type, COUNT(*) FROM <aggregate_table> GROUP BY campaign_type;` on the dev feature store.
6. Record the run result, log-search result and both query outputs in the task notes.

## Acceptance Criteria

- WHEN the dataconsolidation task is run for the Sharawmer configId on dev THE SYSTEM SHALL produce a task log containing zero `Fatal` or `LogTaskFailure` entries [FR-019]
- WHEN the dataconsolidation task finishes THE SYSTEM SHALL leave the Sharawmer aggregate table (`AggregateTable.TableName`) with a row count greater than 0 [FR-019]
- WHEN `SELECT campaign_type ... GROUP BY campaign_type` is run on the Sharawmer aggregate table THE SYSTEM SHALL return only the values 'Acquisition', 'Re-engagement' and '' [FR-019]
- WHEN the aggregate table is compared with the `_main` table THE SYSTEM SHALL show campaign_type 'Acquisition' for App Install campaigns, 'Re-engagement' for App Traffic and App Conversion campaigns, and '' for campaigns matching neither pattern [FR-019]
- Existing tests pass
- New functionality has test coverage
- Code follows repository conventions (see CLAUDE.md)

## Implementation Guide

1. Check the preconditions before running, since none are declared task dependencies. (a) T016 is finished and you have recorded the Sharawmer Kochava feature store `_main` row count and its min/max `date`. (b) `KochavaRedshiftDataAggregator` and `KochavaRedshiftDataConsolidator` are registered in the DataConsolidation case of `IngestionTaskFactory.cs`. (c) The Phase 4 ops items are done: MongoDB `DataSupplierConfig`, the Secrets Manager secret, and the network path to the Kochava RS host. If any precondition fails, stop and report it as a blocker; do not patch code under this task.
2. Run the `dataconsolidation` task for the Sharawmer configId on dev and save the task log.
3. Query `aggregated_kochavaredshift_costandattribution_{configId}` for its row count, min/max `date`, and `SELECT DISTINCT campaign_type`.
4. Re-query the `_main` table for its row count and compare it with the T016 value recorded in step 1.
5. Compare the aggregated count and date range with the `_main` values using the thresholds in the acceptance criteria. If any threshold fails, report a defect against the owning task and do not modify code.
6. Attach the task log and all query outputs as evidence on the task.

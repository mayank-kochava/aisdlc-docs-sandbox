## Implementation Guide

1. Add the new tests to Aim.DataIngestion.Tests/DataSuppliers/KochavaRedshift/KochavaRedshiftReportTests.cs, the path given in the eng-plan. If the file or class does not exist yet when you start, create it at that path. Keep any tests already in it.
2. Build a set of KochavaRedshiftReportModel records and an AppAssociations list with known KochavaId to AppId pairs. Use the real property names from KochavaRedshiftReportModel.cs and KochavaRedshiftConfigModel.cs.
3. Add SwapKochavaAppIds_MatchFound_ReplacesKochavaIdWithAppId, asserting a matching record gets the configured AppId.
4. Add SwapKochavaAppIds_NoMatchForOneRecord_LeavesOriginalAppId. Use a mix of matched and unmatched records and assert the unmatched record keeps its original app id while the matched ones are swapped.
5. Add SwapKochavaAppIds_AllRecordsUnmatched_ThrowsInvalidOperationException, asserting the FR-014b guard throws InvalidOperationException when no record matches.
6. Add Dispose_CalledTwice_DoesNotThrow, calling Dispose() twice on KochavaRedshiftReport and asserting no exception.

## Acceptance Criteria

- WHEN SwapKochavaAppIds runs and a record's KochavaId matches an association THE SYSTEM SHALL replace it with the configured AppId. [BR-02]
- WHEN SwapKochavaAppIds runs and only some records have no matching association THE SYSTEM SHALL leave those records' original app id unchanged. [BR-02]
- WHEN SwapKochavaAppIds runs and every record is unmatched THE SYSTEM SHALL throw InvalidOperationException. [FR-014b, BR-11]
- WHEN Dispose() is called twice on KochavaRedshiftReport THE SYSTEM SHALL not throw. [eng-plan Phase 1: Dispose idempotent]

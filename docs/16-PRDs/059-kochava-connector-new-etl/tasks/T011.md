2. Add SwapKochavaAppIds_MatchFound_ReplacesKochavaIdWithAppId using AppAssociations that match the records.
3. Add SwapKochavaAppIds_NoMatchForOneRecord_LeavesOriginalAppId, where one record has no association and the other records are matched.
4. Add SwapKochavaAppIds_AllRecordsUnmatched_ThrowsInvalidOperationException, which expects the 100% drop guard to fire.

## Acceptance Criteria

- WHEN SwapKochavaAppIds runs and a record's KochavaId has a matching AppAssociation THE SYSTEM SHALL replace it with the configured AppId. [BR-02]
- WHEN SwapKochavaAppIds runs and only some records have no matching association THE SYSTEM SHALL leave the original app id on those records without throwing. [BR-02]
- WHEN SwapKochavaAppIds runs and every record has no matching association THE SYSTEM SHALL throw InvalidOperationException. [FR-014b]
- WHEN Dispose() is called twice on KochavaRedshiftReport THE SYSTEM SHALL not throw. [FR-014b]
- Existing tests pass
- New functionality has test coverage
- Code follows repository conventions (see CLAUDE.md)

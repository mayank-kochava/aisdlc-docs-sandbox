## Implementation Guide

1. For each required environment (dev, QA, prod), create or update the secret `{env}/AIMETLService/Sharawmer` in AWS Secrets Manager.
2. Add exactly two fields: `KochavaRedshiftUsername` and `KochavaRedshiftPassword`.
3. Check the field names match the defaults in KochavaRedshiftConnectorCredential (UsernameSecretKey and PasswordSecretKey) character for character.
4. Fill in the values from the Kochava Redshift credentials owner. Do not paste them into tickets, code or logs, and do not print them when verifying (use the jq check below, which outputs only true or false).
5. Confirm the ETL service role can read the secret.

## Engineering plan
- **Repository:** `mayank-kochava/coding-agent-sandbox` (Go module `github.com/mayank-kochava/coding-agent-sandbox`, Go 1.22). Every task targets this repo.
- **Stack:** Go standard library only (`net/http`, `encoding/json`, `crypto/sha256`, `sync`). No new dependencies, no `go.mod` changes.
- **Packages:**
  - `shortener/store.go`: in-memory `Store` (map + `sync.RWMutex`) with `Save(url) (code string)` and `Lookup(code) (url string, ok bool)`. Code = first 6 chars of base62-encoded sha256 of the URL (deterministic, so FR-4 holds); on a collision with a different URL, append a counter and re-hash.
  - `shortener/validate.go`: `ValidateURL(raw string) error` for FR-2.
  - `shortener/handler.go`: `NewHandler(*Store) http.Handler` routing `/shorten`, `/r/{code}`, `/healthz` (use Go 1.22 `http.ServeMux` method+path patterns).
  - `cmd/shortener/main.go`: listens on `:8081` (env `PORT` overrides), graceful shutdown on SIGINT/SIGTERM.
- **Testing:** table-driven unit tests for store and validate; `net/http/httptest` tests for every handler path and status code. `go test ./...` must pass; `go vet` clean.
- **Order:** store and validate first (independent), then handler (depends on both), then main (depends on handler), then a short README section.
- **Out of scope:** persistence, auth, metrics, custom codes, expiry.

### Requirements
| ID | Requirement |
|---|---|
| FR-1 | Shorten: `POST /shorten` with JSON `{"url": "<http(s) url>"}` returns `201 {"code": "<6 chars>", "short_url": "/r/<code>"}`. |
| FR-2 | Validate: reject a missing, non-http(s), or longer-than-2048-char URL with `400 {"error": "..."}`. |
| FR-3 | Redirect: `GET /r/{code}` returns `302` with `Location: <long url>`; unknown code returns `404`. |
| FR-4 | Idempotent: shortening the same URL twice returns the same code. |
| FR-5 | Health: `GET /healthz` returns `200 ok`. |


## Implementation Guide

1. Open `README.md`, creating it if missing, and append a `## URL Shortener` section. Do not change unrelated existing content.
2. Document how to run it: `go run ./cmd/shortener`, default `:8081`, and the `PORT` override. This describes the behaviour specified for T004. Do not start the binary to verify it, because T004 is not a declared dependency of T007.
3. Document the three endpoints (`POST /shorten`, `GET /r/{code}`, `GET /healthz`). Give a `curl` example and the status codes from FR-1 to FR-5 for each, including 400 and 404. Use a valid example body such as `{"url":"https://example.com"}`, since a URL without a scheme is rejected with 400.
4. State the 2048-character URL limit, that shortening the same URL twice returns the same code, and that storage is in-memory and lost on restart.
5. List what is out of scope: persistence, auth, metrics, custom codes, expiry.
6. Verify with `grep -n "## URL Shortener" README.md` (exactly one match) and the greps in `test_cmd`. Confirm `go vet ./... && go test -race ./...` is still green, then commit with `git add README.md && git commit -m "docs: document URL shortener service"`.

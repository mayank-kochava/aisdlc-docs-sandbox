## Engineering plan
- **Repository:** `mayank-kochava/coding-agent-sandbox` (Go module `github.com/mayank-kochava/coding-agent-sandbox`, Go 1.22). Every task targets this repo.
- **Stack:** Go standard library only (`net/http`, `encoding/json`, `crypto/sha256`, `sync`). No new dependencies, no `go.mod` changes.
- **Packages:**
  - `shortener/store.go`: in-memory `Store` (map + `sync.RWMutex`) with `Save(url) (code string)` and `Lookup(code) (url string, ok bool)`. Code = first 6 chars of base62-encoded sha256 of the URL (deterministic, so FR-4 holds); on a collision with a different URL, append a counter and re-hash.
  - `shortener/validate.go`: `ValidateURL(raw string) error` for FR-2.
  - `shortener/handler.go`: `NewHandler(*Store) http.Handler` routing `/shorten`, `/r/{code}`, `/healthz` (use Go 1.22 `http.ServeMux` method+path patterns).
  - `cmd/shortener/main.go`: listens on `:8081` (env `PORT` overrides), graceful shutdown on SIGINT/SIGTERM.
- **Testing:** table-driven unit tests for store and validate; `net/http/httptest` tests for every handler path and status code. `go test ./...` must pass; `go vet` clean.
- **Order:** store and validate first (independent), then handler (depends on both), then main (depends on handler), then a short README section.
- **Out of scope:** persistence, auth, metrics, custom codes, expiry.

## Implementation Guide

1. Add `TestShorten` to `shortener/handler_test.go` as a table of `POST /shorten` requests sent through `NewHandler(NewStore())` with `httptest`. Cover a valid URL such as `https://example.com` (201), the same URL again (same code), a missing url or `{}` (400), a non-http(s) URL (400), a URL over 2048 characters (400), malformed JSON (400) and a body over 1 MiB (400). Assert `Content-Type: application/json` on error responses too.
2. Run `go test ./shortener/...` and confirm the new cases fail with 404 or 405.
3. In `shortener/handler.go`, add a `writeJSON(w, status, v)` helper and a `(h *handler) shorten` method. Wrap the body with `http.MaxBytesReader(w, r.Body, 1<<20)` and decode into `struct{ URL string `json:"url"` }`.
4. On a decode error, return 400 `request body too large` if `errors.As(err, new(*http.MaxBytesError))` matches, otherwise 400 `invalid request body`. Both use the `{"error": ...}` shape.
5. Call `ValidateURL` and return 400 `{"error": err.Error()}` on failure. Otherwise call `h.store.Save` and return 201 with `{"code": code, "short_url": "/r/" + code}`. Register `"POST /shorten"` in `NewHandler`.
6. Run `go vet ./... && go test -race ./...`, then commit with `git add shortener && git commit -m "feat(shortener): add POST /shorten with validation and idempotent codes"`. Do not use a built server binary. It belongs to T004, which T005 does not depend on, so `httptest` is the only check.

## Acceptance Criteria

- WHEN `POST /shorten` receives a valid http(s) URL THE SYSTEM SHALL respond 201 with JSON `{"code": <6 chars>, "short_url": "/r/<code>"}` [FR-1]
- WHEN `POST /shorten` receives a missing, non-http(s) or longer-than-2048-character URL THE SYSTEM SHALL respond 400 with JSON `{"error": "..."}` carrying the `ValidateURL` message [FR-2]
- WHEN `POST /shorten` receives malformed JSON THE SYSTEM SHALL respond 400 with `invalid request body`, and for a body over 1 MiB SHALL respond 400 with `request body too large` [FR-2]
- WHEN the same URL is posted to `POST /shorten` twice THE SYSTEM SHALL return the same code both times [FR-4]
- WHEN `POST /shorten` returns an error response THE SYSTEM SHALL set `Content-Type: application/json` [FR-2]
- Existing tests pass
- New functionality has test coverage
- Code follows repository conventions (see CLAUDE.md)

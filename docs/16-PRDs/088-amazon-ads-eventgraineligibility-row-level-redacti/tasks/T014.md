## Acceptance Criteria

- BR-1: The redaction decision is **per conversion**, driven solely by Amazon's `eventGrainEligibility` value on that conversion's claim response. -- the behaviour this task contributes to works as described.
- BR-2: `eventGrainEligibility` equal to `"UNRESTRICTED"` (after trimming whitespace, case-insensitive) → **show** (no masking). Any other value — `"RESTRICTED"`, missing, null, empty, or unrecognized — → **mask** (fail-closed). -- the behaviour this task contributes to works as described.
- BR-3: The fail-closed interpretation of a missing/null/unknown eligibility value lives **only at the ingestion decision point**. It is the ingestion layer that resolves ambiguity into a definite restricted/unrestricted flag. -- the behaviour this task contributes to works as described.
- BR-4: Downstream consumers key **only on the resolved per-conversion flag** (`row_level_restricted`). Flag present and true → redact. Flag absent → show. Downstream consumers never read or interpret `eventGrainEligibility` themselves. -- the behaviour this task contributes to works as described.
- BR-5: The decision is **not** role-, user-, or account-based. It applies identically to every viewer of row-level output. -- the behaviour this task contributes to works as described.
- BR-6: Masking **masks columns, never removes rows**. Every conversion (restricted and unrestricted) remains present in row-level output; only Amazon-sourced columns on restricted rows are replaced. -- the behaviour this task contributes to works as described.
- BR-7: Masked value is `---` for string columns and `NULL` for numeric/time columns. -- the behaviour this task contributes to works as described.
- BR-8: Masking applies only to **Amazon-sourced fields and values derived from them**. Non-Amazon fields and network/tracker columns always remain visible, including on restricted rows. -- the behaviour this task contributes to works as described.
- BR-9: Masking applies to **row-level outputs only**: Query reports, Detail reports, exports, and postbacks. **Aggregate outputs read unredacted data** and report unmasked values/counts for all 13954 conversions. -- the behaviour this task contributes to works as described.
- BR-11: Enforcement is gated by a single ingestion-layer setting, the **enforce-from timestamp** (unset = off), compared against the claim time in the same process. Before enforce-from, no conversion is flagged, so nothing is masked anywhere and every output byte is identical to today's output. -- the behaviour this task contributes to works as described.
- BR-12: Conversions ingested before enforce-from are never flagged and are never reprocessed; they remain unmasked permanently, including when re-read after enforcement is enabled. No historical backfill occurs. -- the behaviour this task contributes to works as described.
- BR-13: Scope is **network 13954 only**. All other networks (including Snap/TikTok/Reddit and any other configured network) are unchanged in behavior. -- the behaviour this task contributes to works as described.
- BR-14: The postback sent to Amazon itself (the attributed network's own postback) stays **raw** by default. [DECISION REQUIRED: DEC-001] -- the behaviour this task contributes to works as described.
- BR-15: No new BigQuery tables or schemas are created for 13954. Existing per-app tables are reused. -- the behaviour this task contributes to works as described.
- BR-16: The exact canonical list of Amazon-sourced columns/keys to mask is **frozen from a QA capture** that confirms the flag reaches every conversion type before enforcement is enabled. Until frozen, the column list is treated as provisional. -- the behaviour this task contributes to works as described.
- BR-17: `row_level_restricted` is only ever written as true, never false. -- the behaviour this task contributes to works as described.
- BR-18: Each claim response is evaluated when it is ingested. A later event inherits the flag of its attributing claim (latest re-engagement claim, else the install claim); there is no reprocessing. -- the behaviour this task contributes to works as described.

## Implementation Guide

1. Open cmd/query/blacklist.go and find the package-level blacklistedDatasets slice.
2. Add the entry "unredacted" to the slice. Substring matching also covers unredacted_app_N and account_N_unredacted.
3. Leave all existing entries unchanged.
4. In cmd/query/blacklist_test.go, add cases for unredacted_app_N and account_N_unredacted that expect the same error as the existing _restricted datasets.
5. Add a regression case showing that normal app_N and account_N datasets are still allowed.

## Acceptance Criteria

- WHEN a query references a dataset named unredacted_app_N THE SYSTEM SHALL reject it with the existing restricted-dataset error. [BR-5, BR-9]
- WHEN a query references account_N_unredacted THE SYSTEM SHALL reject it with the same error for every user and role. [BR-5, BR-9]
- WHEN a query references a dataset not on the blacklist, such as app_N or account_N.analytics, THE SYSTEM SHALL behave exactly as before. [BR-9]

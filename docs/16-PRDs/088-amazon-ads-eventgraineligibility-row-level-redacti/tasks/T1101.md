# T1101: Apply postback privacy keypaths only to flagged conversions when require_restriction_flag is set

## In short

Changes postback privacy handling so that, when a rule is marked as needing the restriction flag, masking applies only to conversions flagged as restricted. Rules without that setting behave exactly as they do today.

## Implementation Guide

1. Read source/var/www/lib/KochavaControl/Api/SanitizationApiClient.php to find where the keypaths endpoint JSON is turned into a `GetKeypathsResponse`. Read Postback.php to find where privacy keypaths are currently applied to a postback. Use these existing code paths and do not invent new names for them.
2. In SanitizationApiClient.php add `public $require_restriction_flag = null` as the last constructor parameter of `GetKeypathsResponse`. Populate it from the endpoint JSON at the parsing point found in step 1, and leave it null when the field is omitted.
3. In Postback.php add `public static function ShouldApplyPrivacyKeypaths($keypaths, $postback): bool`. It returns false when there are no keypaths.
4. When `$keypaths->require_restriction_flag === true`, return true only if `kochava.device.attribution.row_level_restricted === true` in `$postback`, which may be an array or an object. In every other case return true.
5. At the existing call site found in step 1, apply the privacy keypaths only when `ShouldApplyPrivacyKeypaths` returns true.
6. Add tests in PostbackRestrictionFlagTest.php and SanitizationApiClientTest.php for flag true, flag absent, field omitted or null, array and object postbacks, and endpoint parsing.

## Acceptance Criteria

- WHEN `require_restriction_flag` is true and `kochava.device.attribution.row_level_restricted` is true in the postback THE SYSTEM SHALL apply the privacy keypaths. [FR-PBK-001, BR-4]
- WHEN `require_restriction_flag` is true and the flag is absent from the postback THE SYSTEM SHALL NOT apply the privacy keypaths. [FR-PBK-002, BR-4]
- WHEN `require_restriction_flag` is null or omitted THE SYSTEM SHALL apply keypaths as it does today. [NFR-011, FR-ENF-006]
- WHEN the postback is supplied as either an array or an object THE SYSTEM SHALL read the flag correctly. [FR-PBK-003]
- WHEN the keypaths response is parsed or the decision is made THE SYSTEM SHALL use only `row_level_restricted` and SHALL NOT read `eventGrainEligibility` or log raw Amazon data. [BR-4, FR-AUD-003]
- Existing tests pass
- New functionality has test coverage
- Code follows repository conventions (see CLAUDE.md)

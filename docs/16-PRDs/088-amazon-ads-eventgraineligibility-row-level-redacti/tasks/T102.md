## Summary
For Amazon Ads SAN (13954) conversions, Amazon-derived fields are masked in every row-level output when the claim isn't `UNRESTRICTED`. Row-level outputs are Query reports, Detail reports, exports, network postbacks and CAP. Aggregates keep full breakdowns.
Design: **decide upstream, redact by config.**
- **watson** (Amazon module only) makes the per-conversion decision and sets a **generic** claim flag `row_level_restricted: true`. All Amazon knowledge stays in watson.
- **soccer-v2** gets a generic, config-driven option: a network config with `require_restriction_flag` applies its keypaths only to flagged conversions. No partner names in soccer.
- **Control** (network postbacks + CAP) honors the same flag and option in its existing sanitization-api keypath path.
- **Detail workers** (MySQL) apply the existing `report_filtering` column filter per row when the row's claim carries the flag.
- **Aggregate readers** read `unredacted_*` for 13954 rows inside the config window, using the Aggregated Insights config-CTE + UNION ALL pattern.
- **The Amazon field list is data:** `keypath_sanitization` rows (recipients `reporting`, `postback`) plus a `report_filtering` row, frozen from real QA payloads.
- **One switch:** `AMAZON_ADS_EGE_ENFORCE_FROM` on watson. Every other deploy is inert until it's set.

## Spec Excerpts

### 3.2 BigQuery Row-Level Output (BQR)

#### FR-BQR-001 — Flagged conversions are redacted at write time
```gherkin
Scenario: A flagged 13954 conversion is masked in the row-level copy
  Given a 13954 conversion carries row_level_restricted = true
    And network 13954 is configured to apply sanitization only to flagged conversions
  When the conversion is written to the row-level (redacted) output copy
  Then all configured Amazon-sourced keypaths are masked in that copy
    And the full original conversion is written to the unredacted copy unchanged
```

#### FR-BQR-002 — Unflagged 13954 conversions pass through unchanged
```gherkin
Scenario: An unflagged 13954 conversion is not masked
  Given a 13954 conversion does NOT carry row_level_restricted = true
  When the conversion is written to the row-level output copy
  Then no masking is applied
    And its Amazon-sourced fields are present in the row-level copy
    And it is also written to the unredacted copy unchanged
```

#### FR-BQR-003 — Row-level readers consume already-redacted data
```gherkin
Scenario: Query reports, the BQ detail reader, and exports require no read-time masking logic
  Given a 13954 conversion was written to the row-level copy with masking already applied
  When a Query report, the BigQuery detail reader, or an export reads that conversion
  Then it returns the already-masked values with no additional read-time masking step
    And non-Amazon and network/tracker columns on that row are returned unmasked
```

#### FR-BQR-004 — Mixed restricted/unrestricted rows in one account
```gherkin
Scenario: One advertiser account returns both masked and unmasked rows
  Given an advertiser account has both flagged and unflagged 13954 conversions
  When a row-level report is run for that account
  Then flagged rows show masked Amazon fields
    And unflagged rows show their Amazon fields
    And all rows are present in the result
```

#### FR-BQR-005 — Masked value conventions
```gherkin
Scenario Outline: Masked columns use the correct placeholder by column type
  Given a 13954 conversion carries row_level_restricted = true
  When an Amazon-sourced <column_type> column is masked in a row-level output
  Then its value is <placeholder>

  Examples:
    | column_type            | placeholder |
    | string                 | ---         |
    | numeric                | NULL        |
    | time / timestamp       | NULL        |
```

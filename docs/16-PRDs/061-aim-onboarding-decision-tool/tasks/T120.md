## Steps

1. Edit `output/TimelineTab.vue` as a bare `v-data-table` of the 6 milestones (Name, Responsible, computed dates, Status, Notes).
2. Compute est. dates client-side as anchor (`approvedAt`) + `WeekOffset`, week-commencing Monday; never store them.
3. Add the status select and a delay flow: pick a new date, preview the cascade, then confirm. Persist via `PUT /{id}/timeline` and surface a 400 on a bad date.
4. Add the audit-log view over `ChangeLog` (server-stamped `UserEmail`; do not send the author from the client).
5. Add the CSM tier-override toggle, shown only if `isASAdmin`, calling `POST /{id}/tier-override`; handle 403 gracefully and respect the rule 'X to Pro only if auto is Pro'.

## Acceptance Criteria

- [ ] The table shows 6 milestones with dates equal to anchor + weekOffset (Monday week-commencing), anchored on `approvedAt`.
- [ ] A delay shows a preview of the affected milestones and only saves after confirmation; a 400 shows an error and leaves the state unchanged.
- [ ] Both client and CSM can edit status and delay; the audit log lists change entries.
- [ ] The tier-override toggle is hidden for non-admins, and a 403 response shows an error without changing the tier.

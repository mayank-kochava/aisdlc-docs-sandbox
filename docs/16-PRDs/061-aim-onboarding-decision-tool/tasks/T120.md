## Steps

1. In `output/TimelineTab.vue`, render a bare `v-data-table` of the 6 milestones. Compute estimated dates as `anchor + WeekOffset` (week-commencing Monday) with the anchor taken from `approvedAt`; never store computed dates.
2. Add an inline status select per milestone and notes; persist through `PUT /{id}/timeline`.
3. Implement delay as: pick new date, preview the cascade of downstream milestones, then confirm before saving. Handle the 400 bad-date response.
4. Add an audit-log view listing `ChangeLog` entries (At, UserEmail, Type, Field, OldValue, NewValue).
5. Add the CSM tier-override toggle, shown only when `isASAdmin` and calling `POST /{id}/tier-override`. Handle 403 gracefully and keep the rule that X can go to Pro only if the auto tier is Pro.

## Acceptance Criteria

- [ ] The table shows 6 milestones with dates computed from `approvedAt` plus week offset, snapped to week-commencing Monday.
- [ ] Changing a delay shows a preview of the cascaded dates, and nothing is saved until the user confirms.
- [ ] A bad-date 400 shows an error and leaves the timeline unchanged.
- [ ] The audit log shows change-log entries.
- [ ] The tier-override toggle is hidden for non-CSM users, and a 403 response is handled without breaking the UI.

## Steps

1. Build `output/TimelineTab.vue` as a bare `v-data-table` showing the 6 milestones.
2. Compute estimated dates client-side from the anchor (`approvedAt`) plus `weekOffset`, as week-commencing Monday. Do not store them.
3. Add a status select per milestone, and a delay flow that previews the new date before the user confirms.
4. Implement the cascade to later milestones, with a preview before confirm, and send changes through the `timeline` PUT. Surface a 400 for a bad date.
5. Add an audit-log view of `ChangeLog`.
6. Add the CSM tier-override toggle, shown only when `isASAdmin` is true and posting to `tier-override`. Handle 403 gracefully and show the server rule that X can go to Pro only if the auto tier is Pro.

## Acceptance Criteria

- [ ] The table shows 6 milestones with dates computed from the anchor and `weekOffset` (Monday week-commencing).
- [ ] A delay shows the new-date preview and applies only after confirm, and the cascade updates later milestones.
- [ ] Status changes and delays are saved via the `timeline` PUT and appear in the audit-log view.
- [ ] The tier-override toggle is hidden for non-admins, and a 403 response shows an error without breaking the UI.
- [ ] A 400 bad-date response is displayed to the user.

## Steps

1. Create OnboardingTimelineService.cs (Services/Onboarding) and OnboardingTimelineController.cs (Api/Areas/App/Controllers). Start after T007.
2. Implement `PUT /{id}/timeline` for milestone status, notes, and a new date stored as `DelayedToDate`. Both client and CSM may call it.
3. Return 400 for an invalid date.
4. Implement the cascade recompute of downstream milestone dates as a pure, separately testable function.
5. Append one ChangeLog entry per edit, with `UserEmail` stamped server-side from the session email (`x-user-id`).
6. Persist the timeline through the data layer.

- [ ] Both a non-admin advertiser user and a CSM can call the endpoint successfully.
- [ ] Downstream milestone dates are recomputed after a delay.

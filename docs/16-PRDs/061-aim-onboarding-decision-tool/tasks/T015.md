## Steps

1. Create `OnboardingTimelineService` in `Kochava.Aim.Portal.Services/Onboarding/OnboardingTimelineService.cs` and `OnboardingTimelineController` in `Kochava.Aim.Portal.Api/Areas/App/Controllers/OnboardingTimelineController.cs`. Start after T007.
2. Add `PUT /{id}/timeline`. It is allowed for both client and CSM, so it has no CSM guard.
3. Support edits to milestone `Status`, `Notes`, and a new-date delay stored as `DelayedToDate`.
4. Implement the cascade recompute as a pure function, so it is unit-testable. The plan says est. dates are `anchor + weekOffset`, week-commencing Monday.
5. Append one `ChangeLog` entry per edit. `UserEmail` is server-stamped from the session email.
6. Return 400 for an invalid date.

## Acceptance Criteria

- [ ] A new delay date is stored in `DelayedToDate`.
- [ ] Each edit adds exactly one `ChangeLog` entry, with `UserEmail` taken from the session and not from the request body.
- [ ] An invalid date returns 400.
- [ ] Cascade recompute behaviour is covered by NUnit cases, or a follow-up test task is noted, since the plan flags cascade math as a risk.

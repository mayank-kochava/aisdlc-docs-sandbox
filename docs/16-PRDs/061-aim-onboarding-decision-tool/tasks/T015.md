## Steps

1. Create `OnboardingTimelineService` in Kochava.Aim.Portal.Services/Onboarding/OnboardingTimelineService.cs and `OnboardingTimelineController` (PUT `/{id}/timeline`) in Kochava.Aim.Portal.Api/Areas/App/Controllers/OnboardingTimelineController.cs, after T007.
2. Support edits to milestone Status, Notes and a delay. Store a new date as `DelayedToDate`.
3. Validate dates and return 400 for a bad date.
4. Implement cascade recompute of the affected milestones as a pure, testable function. Estimated dates are `anchor + weekOffset`, week-commencing Monday, and are not stored.
5. Append one ChangeLog entry per edit, with `UserEmail` stamped server-side from the session email and never taken from the request body.
6. Allow both client and CSM callers; do not apply the CSM guard.

- [ ] Non-CSM advertiser users can call the endpoint successfully.

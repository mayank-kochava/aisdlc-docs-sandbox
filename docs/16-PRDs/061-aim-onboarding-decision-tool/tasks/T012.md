## Steps

1. Create `OnboardingCsmService` (listed under modify, but new) and `OnboardingCsmController` with `POST /{id}/approve` and `POST /{id}/tier-override`. Do this after T011.
2. Call `OnboardingCsmGuard` first in both operations so non-admins get 403 before any data access.
3. `approve`: set `ScopeOfWork.CsmApproved = true` on the session and save it.
4. `tier-override`: set `Tier.Override` with the asymmetric rule. An override from X to Pro is allowed only when the auto-recommended tier is Pro; otherwise reject with a clear error.
5. Append a mandatory `ChangeLog` entry for the override, with `UserEmail` stamped server-side from the user context.
6. Return the updated `OnboardingSessionDto`.

## Acceptance Criteria

- [ ] A non-admin calling `approve` or `tier-override` gets 403 and the session is not modified.
- [ ] `approve` by an admin sets `CsmApproved` to true.
- [ ] `tier-override` X to Pro is rejected unless the auto tier is Pro.
- [ ] Every successful override appends one change-log entry with a server-stamped `UserEmail`, `Field`, `OldValue` and `NewValue`.
- [ ] Both routes are `POST` under `/{id}/` on the onboarding-sessions base.

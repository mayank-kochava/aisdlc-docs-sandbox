## Steps

1. Create `OnboardingCsmService` (`Kochava.Aim.Portal.Services/Onboarding/OnboardingCsmService.cs`) and `OnboardingCsmController` (`Kochava.Aim.Portal.Api/Areas/App/Controllers/OnboardingCsmController.cs`) after T011.
2. Implement `POST /{id}/approve`: call `OnboardingCsmGuard` first, then set `ScopeOfWork.CsmApproved`.
3. Implement `POST /{id}/tier-override`: call the guard, then set `Tier.Override`.
4. Enforce the asymmetric rule: an override from X to Pro is allowed only when the auto-computed tier is Pro. Reject other cases with a validation error.
5. Append a mandatory `ChangeLog` entry for each tier override, with `UserEmail` stamped server-side.
6. Map guard denial to 403 via `HandleDataUpdateResult`/`ForbidWithReason`.

- [ ] An admin calling `approve` sets `CsmApproved` on the session.
- [ ] A tier override outside the allowed X-to-Pro rule is rejected.
- [ ] Every successful tier override appends a `ChangeLog` entry with the server-stamped user email, old value and new value.

## Steps

1. Extend `useAimOnboarding.ts` (after T108) with a load-latest call on mount using `onboardingService.getLatest`. Treat a 404 as a new session and hydrate state from the returned session.
2. Add a localStorage buffer that writes on every state change, and use it when the API is unreachable.
3. Add a debounced full-document PUT (`update`) triggered on step switch, tab switch and manual save. Use `create` (POST) for the first save.
4. Expose a save status of `saving|saved|failed|offline`. Retry after a failure.
5. Add a single in-flight guard so overlapping PUTs are not sent. If changes arrive mid-flight, send one more PUT afterwards.
6. Handle 409 (session already approved) by stopping autosave, marking the session read-only/approved, and surfacing the state to the UI.

## Acceptance Criteria

- [ ] State loads from the latest session on mount, and a 404 yields a fresh session.
- [ ] Only one PUT is in flight at a time, and rapid changes are debounced.
- [ ] The status transitions through `saving`, `saved`, `failed` and `offline` correctly.
- [ ] A 409 response stops further autosave attempts and flags the session as approved.
- [ ] Local edits survive a failed or offline save through the localStorage buffer.

## Steps

1. Extend `useAimOnboarding.ts` (after T108) with a localStorage buffer written on state change.
2. Implement a debounced full-document `onboardingService.update` (PUT), triggered on step change, tab switch and manual save. Create the session through `create` when none exists.
3. Expose a save status of saving/saved/failed/offline. Retry on failure, and go offline when there is no connectivity.
4. On mount, load the latest session via `getLatest`, treating 404 as new, and reconcile with the localStorage buffer.
5. Add a single in-flight guard so overlapping PUTs do not run concurrently.
6. On a 409 (session approved), stop autosaving and surface a locked/read-only state.

- [ ] The latest session loads on mount, and 404 leads to a fresh session.
- [ ] A 409 response stops further saves and puts the composable in a locked state.

## Steps

1. Extend `useAimOnboarding.ts` to load the latest session on mount via `onboardingService.getLatest` (404 means a new session).
2. Buffer state in localStorage on every change.
3. Add a debounced full-document PUT (POST on first save) triggered on step change, tab switch and manual save.
4. Expose a save status of saving/saved/failed/offline and the manual save action.
5. Add a single in-flight guard so overlapping PUTs do not clobber newer state (last write wins on `UpdatedAt`).
6. On 409 (session approved) stop autosaving, mark the session read-only and surface it in state.

## Acceptance Criteria

- [ ] On mount the composable loads the latest session, or starts a new one when the API returns 404.
- [ ] Only one PUT is in flight at a time; a change made during a save triggers a follow-up save.
- [ ] A failed save sets status `failed` and keeps the localStorage buffer; being offline sets `offline`.
- [ ] A 409 response stops autosave and marks the session approved/read-only.
- [ ] The debounced PUT sends the full document.

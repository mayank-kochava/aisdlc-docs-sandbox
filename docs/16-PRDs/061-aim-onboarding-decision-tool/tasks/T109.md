## Steps

1. In `useAimOnboarding.ts`, load the latest session via `onboardingService.getLatest` on mount, with a 404 meaning a fresh session that is created on first save.
2. Buffer state to localStorage on every change.
3. Send a debounced full-document PUT on step change, tab switch and manual save.
4. Expose a save status of saving, saved, failed or offline. Keep the buffer and allow retry on failure.
5. Add a single in-flight guard so overlapping PUTs are not sent; queue or skip and send the latest state after the pending PUT completes.
6. Handle 409 (session approved) by stopping autosave and surfacing a locked state.

- [ ] A 409 response stops autosave and marks the session locked.

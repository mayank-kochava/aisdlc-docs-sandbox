## Steps

1. Extend `useAimOnboarding.ts` after T108 with a localStorage buffer that writes state on change.
2. Load the latest session on mount via `onboardingService.getLatest`. Treat a 404 as a new session and create it via `create`.
3. Add a debounced full-document PUT via `update` on step switch, tab switch and manual save.
4. Expose a save status of saving, saved, failed or offline.
5. Add an in-flight guard so overlapping PUTs are not sent, and retry after a failure.
6. Handle a 409 after approval by marking the state read-only and surfacing the message.

## Acceptance Criteria

- [ ] Only one PUT is in flight at a time, and changes made during a save are sent in the next save.
- [ ] On mount the latest session is loaded, and a 404 results in a new session.
- [ ] A save failure sets the status to failed, keeps the localStorage buffer and allows retry.
- [ ] A 409 response puts the composable in an approved/read-only state and stops further autosave attempts.
- [ ] The status is exposed as one of saving/saved/failed/offline.

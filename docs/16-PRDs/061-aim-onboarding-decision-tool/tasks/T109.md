## Steps

1. Extend `useAimOnboarding.ts` to load the latest session on mount via `onboardingService.getLatest`.
2. Add a localStorage buffer that is written on every change.
3. Add a debounced full-document PUT (via `onboardingService.update`) triggered on step switch, tab switch and manual save. Use `create` when no session exists.
4. Expose a save status of saving/saved/failed/offline.
5. Add a single in-flight guard so overlapping PUTs do not clobber newer state. On failure keep the local buffer and retry.
6. Handle a 409 after approval by marking the session locked and read-only.

## Acceptance Criteria

- [ ] On mount the composable loads the latest session, or starts fresh on 404.
- [ ] Rapid edits produce one debounced PUT, and a second save is not sent while one is in flight.
- [ ] A failed PUT sets status `failed` and preserves the local buffer for retry.
- [ ] A 409 response locks editing and surfaces the approved state.
- [ ] Status cycles through saving, saved, failed and offline as appropriate.

## Steps

1. In `useAimOnboarding.ts`, add a localStorage buffer that writes on state change.
2. Add a debounced full-document PUT via `onboardingService.update`, triggered on step change, tab switch and manual save. Load the latest session on mount with `getLatest`. If none exists (404), start a new session and `create` it on the first save.
3. Expose a save status of `saving|saved|failed|offline`. On failure keep the buffered state and allow retry.
4. Add a single in-flight guard so overlapping PUTs are not sent. Queue or coalesce the newer state.
5. Handle a 409 after approval: stop autosave, keep the status honest, and surface a locked state to the UI.

## Acceptance Criteria

- [ ] Changes are buffered to localStorage, and PUT is debounced and fires on step change, tab switch and manual save.
- [ ] The latest session is loaded on mount, and state is hydrated from it.
- [ ] Only one PUT is in flight at a time.
- [ ] A failed save leaves the status `failed` (or `offline`) and keeps the data for retry.
- [ ] A 409 stops further autosave and exposes a locked/approved state.

## Steps

1. Extend `useAimOnboarding.ts` to load the latest session via `onboardingService.getLatest` on mount, treating a 404 as no session.
2. Add a localStorage buffer written on every change, and a debounced full-document PUT on step switch, tab switch and manual save (POST first if no session exists).
3. Expose a save status of saving, saved, failed or offline, with retry after failure.
4. Add a single in-flight guard so overlapping PUTs are not sent, and resend the latest state afterwards.
5. Handle a 409 response (session approved) by stopping autosave and surfacing a read-only or locked state.

## Acceptance Criteria

- [ ] Mount loads the latest session and populates state.

- [ ] The status transitions among saving, saved, failed and offline as expected.
- [ ] A 409 stops further PUT attempts and sets a locked/approved state.
- [ ] Failed saves keep the localStorage buffer.

## Steps

1. In `useAimOnboarding.ts`, load the latest session on mount via `onboardingService.getLatest`. A 404 means start fresh with `create`.
2. Buffer state to localStorage on every change, and send a debounced full-document `update` (PUT) on step change, tab switch and manual save.
3. Expose a save status of saving, saved, failed or offline. Failed and offline saves keep the localStorage buffer and retry.
4. Add a single in-flight guard so overlapping PUTs are not sent, with the newest state sent after the current PUT completes.
5. On a 409 after approval, stop autosaving, mark the session locked and surface that state to the UI.

## Acceptance Criteria

- [ ] Mount triggers `getLatest`, and state is populated from the response.
- [ ] Rapid edits produce one debounced PUT, and never two concurrent PUTs.
- [ ] The status transitions saving to saved on success and to failed or offline on error, with the localStorage buffer retained.
- [ ] A 409 response stops further autosave attempts and exposes a locked/approved flag.

## Steps

1. In `useAimOnboarding.ts`, on mount call `onboardingService.getLatest` and hydrate state. Treat a 404 as no session yet and create one on first save.
2. Buffer state to localStorage on every change.
3. Send a debounced full-document `update` PUT on step change, tab switch and manual save. Expose the status `saving|saved|failed|offline`.
4. Guard against overlapping PUTs: a single in-flight request, with the latest state queued after it.
5. On failure keep the localStorage buffer and allow retry. Handle a 409 by marking the session approved/locked and stopping further autosave.

## Acceptance Criteria

- [ ] State loads from the latest session on mount.
- [ ] Only one PUT is in flight at a time, and a queued save follows.
- [ ] Failure sets `failed` (or `offline`), keeps the local buffer, and a retry can succeed.
- [ ] A 409 response locks editing and stops autosave.
- [ ] Type-check and lint pass.

## Steps

1. In Kochava.Aim.Portal.Common/Identity/AdminResolver.cs, implement a resolver that calls the mos-iam `GetUserByEmail` client with the caller's `x-user-id` value (the email) and reads `is_as_admin`. Create the file if it does not exist yet.
2. Cache the lookup result per user.
3. Fail closed: if the mos-iam call throws, times out or returns no user, return false.
4. Add `IsAsAdmin` to `ICurrentUserContext` in Kochava.Aim.Portal.Common/Identity/ICurrentUserContext.cs.
5. Populate `IsAsAdmin` in Kochava.Aim.Portal.Api/Filters/AdvertiserContextActionFilter.cs using the resolver.
6. Register the resolver with the existing DI setup if it is not auto-registered.

## Acceptance Criteria

- [ ] `ICurrentUserContext.IsAsAdmin` is true only when mos-iam reports `is_as_admin` = true for the email in `x-user-id`.
- [ ] A mos-iam error, timeout or missing user yields `IsAsAdmin == false` (fail closed).
- [ ] A repeated lookup for the same user within the cache lifetime does not call mos-iam again.
- [ ] The flag is set by AdvertiserContextActionFilter, so it is available to onboarding controllers and services.

Adds a small time-source abstraction plus a controllable fake clock. This lets the rate limiter be tested by moving time forward on demand instead of waiting.

## Engineering plan
- **Repository:** `mayank-kochava/coding-agent-sandbox` (Go module `github.com/mayank-kochava/coding-agent-sandbox`, Go 1.22). Every task targets this repo.
- **Design:** one struct holding `tokens float64`, `last time.Time` and a `sync.Mutex`. Each call refills `min(burst, tokens + elapsed*rate)`, then spends. Time comes through a `Clock` interface so tests use a fake clock and never sleep.
- **Stack:** Go standard library only. No new dependencies, no `go.mod` changes.
- **Testing:** table-driven tests with a fake clock; `go test -race ./...` passes, `go vet` clean.

## Implementation Guide

1. Create ratelimit/clock.go in package ratelimit, standard library only (no go.mod changes).
2. Define `type Clock interface{ Now() time.Time }`.
3. Implement `SystemClock() Clock` returning a Clock whose Now() returns time.Now().
4. Define `FakeClock` holding a time.Time, with `NewFakeClock(t time.Time) *FakeClock`, `(*FakeClock).Now()` and `(*FakeClock).Advance(d time.Duration)`.
5. Write ratelimit/clock_test.go covering FakeClock Now/Advance and SystemClock monotonic Now, with no sleeps.
6. Run go vet ./... and go test -race ./ratelimit/...

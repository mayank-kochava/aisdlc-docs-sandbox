## In short

Builds the rate limiter itself: it hands out a limited number of permissions per second and refills them over time. The fallback limits are the owner's choice, so the agent must ask for them and must not invent them.

## User Story

**US1**

**Acceptance:**
- FR-1: `ratelimit.New(rate float64, burst int, clock Clock) *Limiter` creates a limiter that refills `rate` tokens per second up to `burst` tokens; it starts full.
- FR-2: `Allow() bool` takes one token if available and returns true; otherwise returns false without blocking.
- FR-3: Refill is computed lazily from elapsed clock time on each call (no goroutines, no timers). Fractional tokens carry over between calls.
- FR-4: Defaults: `rate <= 0` or `burst <= 0` use a default rate and burst chosen by the owner (Mayank). The numbers are **not written in this document**; the coding agent must ask the owner for them and must not guess.
- FR-5: `Tokens() float64` returns the current token count after refill. Safe for concurrent use.

## Implementation Guide

1. Before writing any default values, ask the owner (Mayank) for the default rate and default burst used when rate <= 0 or burst <= 0 (FR-4). Do not guess. Wait for the answer, then record the two values as named constants in ratelimit/limiter.go with a comment quoting the owner's reply.
2. Create ratelimit/limiter.go with `Limiter` holding rate, burst, tokens float64, last time.Time, mu sync.Mutex and clock Clock (consumes Clock from T001).
3. Implement `New(rate float64, burst int, clock Clock) *Limiter`. Replace rate with the default rate when rate <= 0 and burst with the default burst when burst <= 0, each independently. Use SystemClock() when clock is nil. Start with tokens = burst and last = clock.Now().
4. Add an internal refill under the mutex: tokens = min(burst, tokens + elapsed.Seconds()*rate), then update last. Keep fractional tokens. Use no goroutines or timers.
5. Implement `Allow() bool` (lock, refill, spend 1 if tokens >= 1 and return true, otherwise return false without blocking) and `Tokens() float64` (lock, refill, return tokens).
6. Write table-driven tests in ratelimit/limiter_test.go, with test names starting `TestLimiter`, using FakeClock. Cover start-full, exhaustion, fractional refill, burst cap, nil clock, concurrent Allow/Tokens, and the defaults cases. The defaults tests must assert against the owner-supplied constants rather than hard-coded literals. Run go vet ./... and go test -race ./...

## Acceptance Criteria

- WHEN New is called with rate > 0 and burst > 0 THE SYSTEM SHALL return a limiter whose Tokens() equals burst before any Allow call [FR-1].
- WHEN Allow() is called THE SYSTEM SHALL consume one token and return true if at least one token is available, and otherwise return false immediately without blocking [FR-2].
- WHEN the clock advances between calls THE SYSTEM SHALL add elapsed*rate tokens capped at burst, carrying fractional tokens over, and Tokens() SHALL report the count after refill [FR-3][FR-5].
- WHEN New is called with burst <= 0 (or rate <= 0) THE SYSTEM SHALL substitute the owner-supplied default burst (or default rate) constant, so that a test asserts Tokens() equals the default burst constant and that one second of fake-clock refill after exhaustion adds the default rate constant (capped at burst), with each constant's comment quoting the owner's reply and no agent-chosen values [FR-4].
- WHEN Allow() and Tokens() are called concurrently from multiple goroutines THE SYSTEM SHALL pass `go test -race` with no data races [FR-5].

## Implementation Guide

1. Create utils/date_format.py with module-level logger = get_logger("date-format") from fastmcp.utilities.logging, following the pattern at tools/campaign_tools.py:15-17.
2. Define DATE_EPOCH_KEYS: frozenset[str] = frozenset() as a module-level constant with a comment that its members are added once decisions.md (T004) fixes the in-scope date-field set. T001 does not depend on T004, so do not guess key names. Read the name at call time so tests can monkeypatch it.
3. Implement normalize_dates(obj, *, tool="unknown") as a recursive walker over dict/list/scalar that returns a deep copy and never mutates the input.
4. Rewrite MM/DD/YYYY strings to zero-padded YYYY-MM-DD using stdlib re/datetime only. Pass already-ISO strings through unchanged. Convert epoch ints whose dict key is in DATE_EPOCH_KEYS to YYYY-MM-DD in UTC. Leave all other ints unchanged.
5. For malformed or unparseable date-shaped values (e.g. "13/45/2026"), keep the original value (no fabricated date). Log an anomaly via logger with the tool and field name but never the value, and never raise.
6. Write unit-tests/test_date_format.py covering nested dict/list, single-digit month/day, already-ISO input, malformed input, input non-mutation and deterministic output. For epoch cases, use monkeypatch.setattr("utils.date_format.DATE_EPOCH_KEYS", frozenset({"example_date"})) so the test does not depend on the real set's contents.

## Acceptance Criteria

- WHEN normalize_dates receives a nested structure containing "11/17/2026" THE SYSTEM SHALL return a copy with "2026-11-17" and no MM/DD/YYYY string remaining. [FR-001]
- WHEN normalize_dates receives "03/04/2026" THE SYSTEM SHALL return "2026-03-04" with a two-digit month and day. [FR-002]
- WHEN DATE_EPOCH_KEYS is patched to contain "example_date" and normalize_dates receives {"example_date": 1794009600, "other": 1794009600} THE SYSTEM SHALL return "2026-11-07" for example_date and leave other as the same int. [FR-005]
- WHEN normalize_dates receives a malformed date-shaped value such as "13/45/2026" THE SYSTEM SHALL return the original value unchanged, log an anomaly that omits the field value, and not raise. [FR-007, NFR-003]
- WHEN normalize_dates is called repeatedly with the same input, including already-ISO strings, THE SYSTEM SHALL return identical output each time without modifying the input. [NFR-005]

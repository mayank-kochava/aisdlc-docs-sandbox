5. Write unit-tests/test_campaign_tools_dates.py following the repo pattern of mocking the upstream HTTP/client call with AsyncMock, with fixture results containing US-format dates.
6. Assert on the raw returned text of each of the four tools. For the shared-format check, compare the date strings in the returned text with json.dumps(normalize_dates(fixture)) from utils.date_format, which the TOON path also uses. Do not import or call the TOON wrapper from T003.

## Acceptance Criteria

- WHEN kochava_list_campaigns returns a result containing "11/17/2026" THE SYSTEM SHALL emit text containing "2026-11-17" and no MM/DD/YYYY date. [FR-001, FR-004]
- WHEN kochava_get_campaign, kochava_create_campaign or kochava_update_campaign returns a result with a US-format date THE SYSTEM SHALL render it as YYYY-MM-DD in the returned text. [FR-001]
- WHEN a campaign tool result is serialized THE SYSTEM SHALL keep the same keys, nesting and list lengths as the upstream result, changing only date values. [NFR-002]
- WHEN a campaign tool serializes a fixture THE SYSTEM SHALL emit date strings identical to those from normalize_dates applied to the same fixture, so any other serialization path using normalize_dates renders the same dates. [FR-008]
- Existing tests pass
- New functionality has test coverage
- Code follows repository conventions (see CLAUDE.md)

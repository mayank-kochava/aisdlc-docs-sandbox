## Implementation Guide

1. Open the Dockerfile and find the `go build` `-ldflags` line and any `ARG VERSION`. The plan says this checkout's ldflags may point at a nonexistent `main.Version`, but that text has not been verified, so read the file first.
2. Compare the `-X` target with what the app reads. cmd/household-id-adornment-api/main.go:20 sets `app.Version = gopkgver.Version`.
3. If the target is `main.Version` or anything else, change it to `-X github.com/Kochava/gopkgver.Version=${VERSION}`. Make sure `ARG VERSION` is declared in the build stage before use, with no default value, so a build without `VERSION` keeps gopkgver's built-in `dev`.
4. If the Dockerfile is already correct, record that finding in the PR and make no change.
5. Run the test_cmd. It greps the Dockerfile for the correct symbol and for the absence of `main.Version`. It builds `hid:test` (with `VERSION=1.2.3`) and `hid:nover` (without it), then runs each image with `--version` and checks the printed version. This assumes the image ENTRYPOINT is the app binary and that urfave/cli's default `--version` flag is enabled. If not, add `--entrypoint` or adjust the command and note it in the PR.
